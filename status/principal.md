- **Recent** (≤5):
  - 2026-08-07: **compared the plugin against a running Sub-Store, page by page**, and the comparison was worth more than the features it produced. Three classes of defect, all of them shipped: (1) **most operator arguments were invented rather than derived** — `Regex Filter` stored its patterns under `value` where the engine destructures `regex`, which in keep mode drops EVERY node; `Regex Rename`/`Delete`/`Sort`/`Regex Sort` are handed their value bare and were being wrapped; `Conditional Filter`, `Flag`, `Resolve Domain` and `Add Proxies` all had wrong key names. (2) **the Quick Setting tri-states were booleans** and the engine switches on `"ENABLED"`/`"DISABLED"`, so every switch in the common-settings block was a no-op that looked set. (3) **`.alert-ok` did not exist**, so every "Saved"/"Copied"/"Deleted" in three screens rendered in the failure styling. Also corrected: one chain runs in TWO stages (`process` skips response transformers, `processResponse` runs only those) and this plugin treated them as alternatives, so a subscription could not rewrite its own output; the migration read one endpoint of three, leaving an operator's combinations and files behind, and file generators need lifting out of the chain because upstream stores a placeholder in `content`. Shipped as `0.11.0-alpha.1` — 4 loaded, 0 rejected, data intact, backup verified readable first. The lesson is narrow and general: reading a name and writing a schema against it produces code that type-checks, tests green against its own assumptions, and does nothing.
  - 2026-08-07: **script files** — a file can be built by a JavaScript program rather than stored as text, which is the shape operators actually run. The finding that mattered came from probing rather than reading: the embedded core exposes **only** `ProxyUtils`, and `produceArtifact` / `$content` / `$options` / `$arguments` are injected by upstream's *backend*. A ported generator therefore could not start here at all — not "worked differently", could not start. The plugin now builds that surface before the engine does, so no host call happens mid-eval and it still fits fork-per-call. The load-bearing detail is that `produceArtifact` resolves the source **per member**: upstream tags each proxy with `_subName` and real scripts *filter* on it, so merging first and parsing once would leave the filter keeping nothing and hand a client a configuration with no nodes. Verified by running an operator's real 59 KB generator unmodified — 29,469 bytes of Mihomo config, both source prefixes intact — locally, since real generators carry DNS servers, node names and credentials and are never committed. Scripts live under their own KV key rather than in the record document, which would otherwise re-encode half a megabyte of JavaScript on every unrelated edit. Query parameters are declared per record because a share URL is public; the core does not forward any yet (TASK-0025).
  - 2026-08-07: **TASK-0022 ruled and implemented** — the exclusion list was the oversight, and the state was sharper than the draft said: `Store.PutKV`/`PutStatic` were authoritative through the whole-JSON rewrite, the bolt record-level methods existed with **no caller**, and the merge on open **read both buckets and discarded them**. Half-wired in both directions, so guessing "vestigial" and deleting the buckets would have been wrong. Three changes had to land together; the one worth remembering is that the migration needs a `_meta` flag rather than an is-bolt-empty check, because the JSON file keeps its stale copy until the next write and a second run resurrects every deletion since the first — caught by a test written before the flag existed. Also: `static` had no delete at all, which stops being tolerable the moment something writes an object per record.
  - 2026-08-07: **files shipped** — sub-store `0.10.0-alpha.1`, deployed, `4 loaded, 0 rejected`, data intact, backup verified readable before anything was overwritten. A file is a document the core serves whose proxy list is filled in from a subscription or a combination; it reuses the same store behind `kind: "file"`, so the signed manifest gained no methods and this wave needed no signing gate. Two findings worth keeping. **One:** replacing `proxies` is not enough — every proxy-group still names the example nodes the template was written around, and Mihomo refuses to start on a group pointing at a proxy that is gone, so a config that merged cleanly would have failed at the client with nothing to point at. Stale references are dropped and an emptied group inherits the injected nodes; a group with its own rule is left alone. **Two:** the engine has two operator vocabularies, not one. A response chain and a node chain each skip the other's steps *silently*, and "Response Transformer" is not in the pinned proxy-operator catalogue at all — so a plain-text file could not have had a single working operation. They now validate against separate sets and each palette offers only what can run. Also closed TASK-0024's first DoD bullet: engine errors can carry their original text from a test, guarded so shipped code cannot turn redaction off, and it found the `produce`/`yaml` mismatch on its first run.
